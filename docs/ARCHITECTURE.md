# Architecture

## Goals

1. One-command host setup on Windows/Linux.
2. Browser client that works on PC and mobile without installing a native app.
3. Lower latency than classic framebuffer VNC for game-like motion.
4. Explicit security boundaries: password, loopback bind, control lease, validated input.

## Host pipeline

### Video

`VideoStream` owns one FFmpeg encoder shared by all viewers.

- Capture:
  - Windows: `gdigrab` by default; `ddagrab` is available as an experimental option.
  - Linux: `x11grab` (X11/XWayland).
  - Demo: raw RGB frames generated by Pillow.
- Encode:
  - H.264 with encoder preference NVENC → QSV → AMF → VAAPI (Linux) → libx264.
  - Baseline/zerolatency-friendly settings, 1-second GOP, no B-frames.
  - `h264_metadata=aud=insert` gives explicit access-unit boundaries.
- Packetization:
  - `H264Parser` converts Annex-B NALs into AVCC access units and builds `avcC`.
  - Binary WS frame: `uint8 type | uint32 seq | uint64 pts_us | payload`.
  - Types: keyframe, delta, config, PCM audio, JPEG.
- Backpressure:
  - Per-viewer queue. If a viewer falls behind, the queue is cleared and the client waits for the next keyframe.

### Audio

Audio is optional and isolated from video.

- Windows: `pyaudiowpatch` WASAPI loopback.
- Linux: FFmpeg `-f pulse -i default.monitor`.
- Format: PCM s16le, usually 48 kHz stereo.
- Browser: `AudioWorklet` ring buffer with ~60 ms target and drift dropping.

### Input

- Windows: `SendInput` with scancodes, relative/absolute mouse, wheel, Unicode text.
- Linux: XTest via `python-xlib`; `xdotool` for text when available.
- Gamepad: `vgamepad` virtual Xbox 360 controller; fallback maps pad to keyboard/mouse.
- All held keys/buttons are released on disconnect, control transfer, idle timeout and shutdown.

### Control plane

- REST:
  - `GET /api/meta`: non-secret capabilities.
  - `POST /api/login`: password → session cookie.
  - `POST /api/logout`, `GET /api/session`.
- WebSocket `/ws`:
  - Server → client: hello, control, quality, audio/gamepad status, media bytes.
  - Client → server: ping/stats, control take/release, quality/audio/gamepad mode, validated input.

## Tunnel

`QuickTunnel` runs:

```text
cloudflared tunnel --url http://127.0.0.1:<port> --no-autoupdate --protocol http2
```

It parses the `https://*.trycloudflare.com` URL from logs, prints it and writes
`runtime/session.json` (no password). When the host exits, cloudflared is terminated and the
session file is removed. The public hostname is not stable across restarts.

## Client

- `player.js`: WebCodecs H.264 decode + canvas render; MJPEG fallback via `ImageBitmap`.
- `audio.js` + `audio-worklet.js`: PCM playback.
- `input.js`: keyboard, direct touch/mouse, relative trackpad gestures, pointer lock.
- `gamepad.js`: touch overlay + physical Gamepad API polling.
- `app.js`: auth, WebSocket lifecycle, reconnect, settings, fullscreen, wake lock, stats.

## Deliberate non-goals for 1.0

- No file transfer or remote shell.
- No multi-monitor switching UI yet (CLI `--monitor` exists).
- No Wayland-native PipeWire capture.
- No persistent named-tunnel management UI.
- No claim of competitive-game latency over the public Internet.
